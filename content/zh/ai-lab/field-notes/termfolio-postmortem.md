> **交付里程碑：2026-10-27。** Termfolio 预览、字体和 Bitmap 素材以及静态客户端脚本分别在当天提交。此日期表示可运行预览交付，并不代表部署平台上的服务端 API 已上线。

## 框架选择带来的边界

用户确认可以直接基于 `wa1939/termfolio`，关键判断是尊重源项目的 Next.js/React 运行模型，而不是把 React 组件硬塞进 Hugo 模板。仓库最终同时存在独立 Next.js 应用与 Hugo 主题中心中的终端入口：前者负责完整应用交互，后者负责发现和预览。共享文章数据、图片路径和本地服务端能力不能因为同属一个 Git 仓库就假设自动共享。

## 三类真实碰壁

第一，页面能打开却主要显示英文。根因不是字体，而是 locale 文案、中文内容源和语言切换路由不是同一套数据契约；仅翻译按钮不会翻译文章正文。第二，文章图像或相关插画无法显示/点击后跑到 Icons8 官网。根因是外部页面地址被当作图片地址或卡片目标，且静态客户端脚本与 public 资产在发布目录中的路径处理不一致。第三，模型密钥最初被描述成“前端加密”。浏览器拿到的密钥可以被用户检查，混淆和打包不构成秘密保护；静态 GitHub Pages 也没有 Next.js API Route 的运行时。

## 修复和安全模型

应用保留 Next.js App Router，中文文章读取仓库本地 Markdown，语言路径与文案统一由 locale adapter 生成。图片改为本地清洁衍生素材，来源和许可记录与生产展示资源分开；文章卡片仍链接站内文章，不把作者或素材页面当成阅读目标。字体、图片和脚本则经过构建产物检查，而不只在开发服务器上确认。

Agnes 调用放在服务端 `/api/agnes/chat`，密钥从 `AGNES_API_KEY` 环境变量读取并受请求大小、历史条数、超时和错误映射约束。安全目标是密钥不进入客户端 bundle，而不是“加密后放在前端”。因此需要支持服务端函数的部署目标；单靠静态 Pages 不能承载该接口。

## 前后差异与学习方法

前期有英文页面、断链素材和部署模型误判；收敛后是中文优先的独立 Next.js 应用、站内文章路由、本地插画目录与服务端密钥边界。10 月 27 日提交记录证明预览、字体/Bitmap 资源和客户端脚本已纳入交付；没有据此声称生产 API 已部署，也没有引用未经运行的性能指标。

实习生可用“密钥在哪里、内容从哪里来、每个链接要去哪里、构建后文件在哪里”四个问题做费曼复述。若一句话里说不清静态资源与服务端 API 的部署边界，就先画请求链路，再开始写配置。素材方面还要逐个确认来源许可；网页可以访问不等于素材可再发布，学习许可也不自动授予去水印或重新分发的权利。
